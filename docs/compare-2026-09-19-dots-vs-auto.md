# 对照实验：dots 钉死 vs auto 异构车道（2026-09-19）

同一目标（洛谷 P2482 猪国杀）、同一 4 人、同一 15 分钟墙钟、同一预算上限。
唯一变量 = 模型选法。两份数据都是账本实测。

| 指标 | dots 钉死（4×dots3-note-prev）| auto（keypool 异构 4 条车道）|
|---|---|---|
| 调用次数 | 50 | **108**（2.2×）|
| 失败率 | 10 / 20.0% | **4 / 3.7%** ✅ |
| 「没有调用任何工具」 | 5 | **0** ✅ |
| 平均单次延迟 | 17.9 s | **8.4 s** ✅ |
| 花费 | $1.1963 | $3.1223（2.6×）❌ |
| 单次调用均价 | $0.0239 | $0.0289 |
| tokens | 664,603 | 1,734,593 |
| 邮件（群发/点对点）| 12（3/9）| 11（2/9）|
| 认领 / 多人同干 | 4 / 2 | 1 / 1（该窗口）|
| **交付** | **0** ❌ | **0** ❌ |
| 主文件被几人写 | 3 人（write 工具 ×5）| **≥4 人**（bash heredoc + write）❌ |
| 产物质量 | 编译通过 ✅ 末行错（`J J J D`）| 编译通过 ✅ **样例跑死循环**（30s 超时）❌ |

## 结论

1. **mechanically auto 明显更强**：失败率 20% → 3.7%、no-tool 5 → 0、单次延迟 17.9s → 8.4s、
   同样 15 分钟里干的活多 2.2 倍。而且 auto 那轮**真的在做验收** —— justin 跑了 `bash test.sh`，
   30 秒超时（退出码 124）当场抓到死循环，只是没时间修了。dots 那轮从头到尾没有机械验收。
2. **但贵 2.6 倍**（每 token 更贵 + 干得更多）。
3. **两轮交付都是 0** —— 这不是模型问题，是系统问题（B3）。
4. **B2 的提示词层修复无效**：agent 主要用 `cat > p2482.cpp << 'CPPEOF'` 这种 bash heredoc 写文件，
   绕过 write 工具，所以「文件独占」规则既管不到、账本里的 write 事件也看不见。

## 新增 bug

### 📋 B10 文件写入的 bash 通道（B2 的真正拦路虎）
- 现场：auto 那轮 p2482.cpp 被 ruth（bash heredoc ×2）、justin（bash 追加 ×1）、evelyn（write 工具 ×2）
  先后写入 —— 4 个写者，其中 3 次完全不经过 write 工具，`write` 事件里只看得见 2 次。
- 影响：文件独占/覆盖预警在提示词层注定失效；「谁写了什么」在账本里是失真的。
- 可选修法（都不需要经理）：① 每步后扫工作区 mtime，把「刚被改的文件」归因到刚跑完 bash 的人，
  记 `file.written` 事件 + 换手时广播一次；② 在 bash 工具里识别 heredoc/重定向目标文件，
  命中别人的 owner 就在 observation 里点名；③ 收工时报告「多人写同一文件」的清单当作交付风险。

### 📋 B11 工具参数 JSON 非法（auto 车道）
- 现场：`调用了不存在的工具：write（参数不是合法 JSON）` ×2。模型输出了坏 JSON，整步作废。
- 建议：把「参数不是合法 JSON」单独计数并回灌一句格式提醒，别和「工具不存在」混为一谈。
