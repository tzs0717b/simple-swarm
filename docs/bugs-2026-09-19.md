## 🔄 进展更新：M12 工作区 git 留档（P1 + P2 已上线）

**B10（bash heredoc 写入绕过 write 工具）→ ✅ 已修**
- 修法不是「堵住 bash」，而是**归因换源**：每步结束后由系统对工作区做一次 git 提交，
  提交者 = 刚动手的那个 agent，改动清单 = 工作区 diff。agent 用什么通道写都跑不掉。
- 实测（scripts/git-check.ts，45 断言）：amy 写 → bob 用 `cat > … << 'EOF'` 覆盖 → 两人各一条历史，
  署名正确；二进制 / >256KB 不进库；`.git` 被 `rm -rf` 后能从工作区外的影子仓库连历史带文件恢复。

**B2（多写者覆盖）→ ✅ 改为「可见 + 可恢复」（不再试图阻止）**
- 提示词层的「文件独占」已删除（实测无效）。取而代之：
  ① 每个文件谁写过、写了几次、最新提交号 → 现场提示里的「文件版本」段；
  ② 同一文件换手时系统**点对点播报**给上一版作者：你那版被谁顶掉了、`git show <sha>:路径` 怎么取回来、
     `git diff <sha> HEAD -- 路径` 怎么先看差异（节流 120s + 单轮上限 12 封）；
  ③ 开工文案改成「git 三条规矩」，并明说：别为怕覆盖而发明新文件名，谁写得对由测试说话。
- 为什么不做裁判：覆盖 = 两种实现竞争，**跑测试**才知道谁对（复检片本来就干这个）。
  系统只保证「没人能偷偷覆盖」和「上一版随时能拿回来」。
