# 质疑机制（challenge）

> 2026-09-19 加入。起因是 pelican-45b 那一轮的复盘。

## 为什么要有这个

那轮复盘发现一件事：**agent 手里其实只有一个被截断到 120 字的目标**
（runner.ts 的 goalOf() 是 goal?.body.slice(0, 120)），加上**它自己那一片的名字**。
也就是说 —— 片名是这个去中心化集群里**唯一的协调媒介**，而写片名的是派工员。

派工员写粗了片（保底切法那版：「主要运动动画 1：主体最核心的那个动作」），
全队就会各交一摊碎片：7 个 SVG 平铺在工作区，没人知道哪个是成品，
最终交付件自称「基本框架」，12 帧动画的相邻帧像素差是 **0.000**。

而当时**没有任何补偿机制** —— 派工员只在开跑前出现一次，之后没人能挑战它。

## 机制

质疑是一等账本对象（ChallengeInfo），不是普通邮件 —— 因为邮件可以被无视，
而质疑必须有「回应义务」和「裁决」才有牙齿。

| 动作 | 工具 | 谁可以做 |
|---|---|---|
| 立案 | challenge | 任何 agent |
| 回应 | respond_challenge | **只有**被质疑者本人 |
| 裁决 | rule_challenge | 任何**第三方**（质疑者和被质疑者自己判无效） |

**被质疑对象**：target 可以是某个 agent、slicer（派工员写的那块板）、或 all（全队）。

**质疑类型**：slicer（片切得不对）／artifact（产物不合规）／evidence（交付说明与事实不符）／duplicate（重复劳动）。

## 三条让它有牙齿的规则

1. **必须带证据**：evidence 少于 8 个字符直接拒收。空口质疑不受理 —— 贴命令、实测数字、文件加行号。
2. **沉默即认账**：超过 SWARM_CHALLENGE_GRACE_MS（默认 6 分钟）没人回应 →
   系统记 challenge.expired 并**按成立处理**（runner.ts 每轮扫一遍，和墙钟闸同一层）。
3. **成立会真的改板**（不是只聊两句）：
   - 质疑派工员成立 → 按质疑者的 ask **往板上新增一片**（slice.added，by=challenge/名字）；
   - 质疑同伴的片成立 → 那片被 claim.released **退回 available、原证据作废**，并新增一片返工要求。

## 反作弊

- **配额**：每人 SWARM_CHALLENGE_QUOTA（默认 3）次。**被驳回扣一格，成立不扣** ——
  所以乱提质疑是有代价的，而指出真问题不亏。
- **去重**：同一质疑者 + 同一目标 + 同一切片 + 前 24 字相同的主张 → 拒收，防复读刷屏。
- **自审无效**：质疑者和被质疑者的 rule_challenge 在系统层被拒（不是靠提示词劝）。

## 旋钮

| 环境变量 | 默认 | 作用 |
|---|---|---|
| SWARM_CHALLENGE_QUOTA | 3 | 每人质疑配额（被驳回才扣） |
| SWARM_CHALLENGE_GRACE_MS | 360000 | 宽限期：多久没人回应就按成立处理（下限 1 秒，便于自检） |

## 自检

~~~bash
cd simple-swarm-server
SWARM_CHALLENGE_GRACE_MS=1200 node scripts/challenge-check.ts
~~~

15 条断言，覆盖：空口拒收 / 质疑派工员成立并改板 / 自审无效 / 别人不能代回 /
驳回扣配额 / 复读去重 / 超时认账。全部是**系统层硬机制**，不靠提示词。
